## Phase 1 — Triage

MUST:
- Check dataset status: `aws lookoutvision describe-dataset --project-name <project> --dataset-type <train|test>`
- Verify S3 bucket and images are accessible: `aws s3 ls s3://<dataset-bucket>/<prefix>/`
- Check manifest file format if using manifest-based import

SHOULD:
- Verify image formats are PNG or JPEG
- Check image count meets minimums (20 normal, 10 anomaly)
- Verify S3 bucket is in the same region as the project

MAY:
- Validate manifest file JSON structure
- Check CloudTrail for dataset creation events

## Phase 2 — Remediate

MUST:
- Ensure S3 bucket is in the same region as the Lookout for Vision project
- Fix manifest file format — must be valid JSON Lines with correct schema
- Verify IAM role has s3:GetObject and s3:GetBucketLocation permissions

SHOULD:
- Convert images to PNG or JPEG if in other formats
- Ensure images are at least 64x64 pixels (512x512+ recommended)
- Validate all manifest entries point to existing S3 objects

MAY:
- Use the Lookout for Vision console for easier dataset creation
- Create a validation script to check manifest and images before import

## Common Issues

- symptoms: "Dataset creation fails with manifest validation error"
  diagnosis: "Manifest file has incorrect JSON format or missing required fields."
  resolution: "Validate manifest JSON Lines format. Each line must have source-ref and class label. Fix formatting errors."

- symptoms: "Import succeeds but dataset shows fewer images than expected"
  diagnosis: "Some images failed validation — wrong format, too small, or S3 path incorrect."
  resolution: "Check dataset status for error details. Fix image formats and S3 paths. Re-import failed images."

## Escalation Conditions

- Dataset import fails with internal errors after fixing manifest and permissions
- S3 bucket is in a different account requiring cross-account access
- Image count is insufficient and more data collection is needed
- Manifest file is generated by external system with format issues

## Data Sensitivity

- `aws lookoutvision describe-dataset`: MEDIUM — reveals dataset configuration and image counts
- `aws s3 ls s3://<dataset-bucket>/`: MEDIUM — reveals image file names
- Manifest file content: MEDIUM — reveals S3 paths and labels
- Training images: HIGH — may contain proprietary manufacturing images

## Prohibited Actions

- NEVER delete a dataset that is referenced by a trained model
- NEVER modify images in S3 while a training job is in progress
- NEVER share training images outside the organization without authorization
- NEVER import unlabeled images — all images must have normal or anomaly labels

## Phase 3 — Rollback

1. If dataset was created with wrong images, delete it: `aws lookoutvision delete-dataset --project-name <project> --dataset-type <type>`
2. If manifest was incorrect, fix and re-import
3. If S3 permissions were changed, restore previous policy
4. Verify no training jobs were affected by dataset changes
5. Document the import issue for the data engineering team
