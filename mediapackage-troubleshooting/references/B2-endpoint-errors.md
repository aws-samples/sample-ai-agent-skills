# B2 — MediaPackage Endpoint Error Responses

## Symptoms
- 403 Forbidden on endpoint requests
- 404 Not Found for manifest or segments
- 500 Internal Server Error

## Triage Commands

```bash
aws cloudwatch get-metric-statistics --namespace AWS/MediaPackage --metric-name EgressResponseTime --dimensions Name=OriginEndpoint,Value=<endpoint-id> --start-time <start> --end-time <end> --period 60 --statistics Average
# Test endpoint directly
curl -v "https://<endpoint-url>/index.m3u8"
```

## Error Code Reference

| Code | Cause | Fix |
|------|-------|-----|
| 403 | CDN auth failed, IP whitelist | Check CDN auth secret, IP allowlist |
| 404 | No content, wrong URL, outside window | Verify ingest active, check URL, startover window |
| 500 | Internal error, packaging failure | Check CloudWatch logs, contact support |
| 502 | Upstream error | Check ingest source health |

## Resolution

- 403: Verify CDN authorization header matches Secrets Manager value
- 404: Confirm channel is receiving ingest, URL path is correct
- 500: Check for packaging configuration issues, review CloudWatch metrics
- For intermittent errors, check EgressResponseTime for latency spikes

## Escalation Conditions

- **Escalate immediately** if the issue involves potential data loss or corruption
- **Escalate immediately** if a production workload is impacted and cannot be restored within the agreed SLA
- **Escalate immediately** if the root cause is unclear after initial diagnostic steps are exhausted
- **Escalate to service team** if the issue appears to be a platform-level bug or undocumented behavior
- **Escalate to security team** if unauthorized access, policy violations, or credential exposure is suspected

## Data Sensitivity

- Verify data classification before performing any read or export operations
- Ensure all troubleshooting outputs (logs, configurations, snapshots) are handled according to the customer's data handling policy
- Mask or redact personally identifiable information (PII) in all shared diagnostics
- Do not copy production data to non-production environments without explicit authorization
- Retain troubleshooting artifacts only for the duration required and dispose of them securely

## Prohibited Actions

- **NEVER** delete an origin endpoint that is actively serving live or VOD content to viewers
- **NEVER** modify DRM key rotation settings during an active live stream
- **NEVER** remove CDN authorization headers from endpoints serving production traffic
- **NEVER** change packaging configurations on live channels without a tested rollback plan
- **NEVER** delete harvest jobs or live-to-VOD assets without confirming content retention requirements

## Phase 3 � Rollback

1. **Identify rollback trigger**: Determine if the applied change has caused degradation, unexpected behavior, or failed validation checks
2. **Preserve current state**: Capture logs, configuration snapshots, and resource states before initiating rollback
3. **Execute rollback steps**: Revert configuration changes in reverse order of application, verifying each step
4. **Validate service recovery**: Confirm that the service has returned to its pre-change operational state using health checks and functional tests
5. **Document rollback**: Record the rollback trigger, steps taken, time to recovery, and any residual issues for post-incident review
