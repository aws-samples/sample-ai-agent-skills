## Phase 1 — Triage

MUST:
- Check if NIST standard is enabled: `aws securityhub get-enabled-standards`
- List NIST controls: `aws securityhub describe-standards-controls --standards-subscription-arn <nist-standard-arn>`
- Get failed NIST findings: `aws securityhub get-findings --filters '{"ComplianceStatus":[{"Value":"FAILED","Comparison":"EQUALS"}],"GeneratorId":[{"Value":"nist-800-53","Comparison":"PREFIX"}]}' --max-results 20`
- Verify Config is enabled: `aws configservice describe-configuration-recorder-status`
- Identify the NIST control families with the most failures

SHOULD:
- Group failures by control family (AC, AU, CM, IA, SC, etc.)
- Check if the failures overlap with CIS or PCI DSS controls
- Verify all required resource types are being recorded by Config

MAY:
- Prioritize controls by severity and impact
- Check for NIST-specific remediation guidance

## Phase 2 — Remediate

MUST:
- Fix the highest-severity control failures first
- Ensure Config is recording all required resource types
- Verify controls pass after remediation

SHOULD:
- Address control families systematically rather than individual controls
- Document remediation for compliance audit evidence
- Enable automated remediation for common failures

MAY:
- Create a NIST compliance dashboard with insights
- Set up notifications for NIST control status changes

## Common Issues

- symptoms: "Large number of NIST controls show NO_DATA"
  diagnosis: "Config is not enabled or not recording all required resource types. NIST has the most controls and requires broad Config coverage."
  resolution: "Enable Config with 'Record all supported resource types' including global resources."

- symptoms: "NIST controls failing that pass in CIS standard"
  diagnosis: "NIST may have stricter requirements for the same underlying check, or the control parameters differ."
  resolution: "Review the specific NIST control requirements. NIST controls may evaluate additional attributes."

## Safety Ratings

| Phase 2 Action | Rating | Rationale |
|---|---|---|
| Fix control failures | YELLOW | Resource changes; varies by control |
| Enable Config with all resource types | YELLOW | Configuration change; reversible |

## Escalation Conditions

- Standard enablement/disablement
- Cross-account configuration changes
- Bulk control remediation

## Data Sensitivity

| Triage Command | Sensitivity | Rationale |
|---|---|---|
| `get-enabled-standards` | LOW | Standard subscription status |
| `describe-standards-controls` | LOW | Control status |
| `get-findings` (NIST) | MEDIUM | NIST compliance findings |

## Prohibited Actions

- NEVER suggest disabling Security Hub
- NEVER suggest disabling all security standards
- NEVER suggest auto-archiving all findings

## Phase 3 — Rollback

| Remediation | Rollback Step |
|---|---|
| Control remediation | Revert resource to previous configuration |
| Config enablement | Stop recorder (not recommended) |
